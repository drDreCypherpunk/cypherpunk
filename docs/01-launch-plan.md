# Launch plan & copy pack

**Rewritten 2026-09-16 for confirmed positioning** (see `05-open-decisions.md`
#7): Cypherpunk is **"The Bitcoin Start-up Engine"** — a Bitcoin-focused
startup accelerator/studio running a cohort-based founder program, backed by
Fulgur Ventures and Initial Capital per the app's own copy. This replaces the
earlier "broad crypto/Web3 community" plan below it in git history, which was
built on a wrong assumption about what Cypherpunk is.

**What changed and why it matters for the plan:**
- The audience is not "crypto-curious people to join a Discord." It's
  **Bitcoin-native founders and builders** deciding whether to apply to a
  12-week cohort — a much smaller, higher-intent, harder-to-reach pool.
  Discord-style broad-community tactics (seed DMs to grow a chat server,
  quest boards, meme culture posts) don't fit; accelerator marketing runs on
  credibility, proof (portfolio companies, named backers), and direct
  founder-to-founder trust.
  - App tab: Home.
- The **primary conversion event is a completed "Apply as Founder"
  application**, not a Discord join or a newsletter signup. Hub (community)
  and Events (Demo Day, meetups) are secondary — they build the pipeline for
  the next cohort and keep alumni/portfolio founders engaged, but the number
  that matters is qualified applications per cohort.
  - App tabs: Accel (the program itself, "Apply as Founder" CTA), CoS
    (portfolio/companies-out-of-the-program), Hub (community/knowledge),
    Events (Demo Day + meetups).
- **Cadence is cohort-shaped, not evergreen.** An accelerator runs on a fixed
  application-window → selection → 12-week program → Demo Day cycle, repeated
  per intake (most accelerators run 2 cohorts/year). The calendar in
  `02-growth-calendar.md` is built around one full cycle, not a flat 24-week
  community ramp.

**Not yet verified, stated plainly:** whether the site's Fulgur Ventures /
Initial Capital backing and the named portfolio companies are live,
confirmed partnerships or design-mock placeholders. Nothing here should
reference them as fact in outbound copy until that's confirmed — see
`05-open-decisions.md`.

## Funnel (replaces the old join-a-Discord funnel)

**Awareness → website visit → "Apply as Founder" click → completed
application → interview → accepted founder (cohort seat).**

- Discord/Telegram-style "hub" growth still matters, but as a *secondary*
  channel: it's where rejected applicants, alumni, and the wider Bitcoin
  builder audience stay warm for the next cohort, not the main goal.
- Every touchpoint's job is to move a builder from "aware of Cypherpunk" to
  "applied," or to move a non-applicant into the Hub/newsletter so they're
  reachable for the next cycle.

## Phase 0 (weeks 1–2): Foundation & positioning
- Lock one sentence a Bitcoin founder repeats to a friend: what Cypherpunk
  gets them that a generic accelerator or VC check doesn't (named backers,
  Bitcoin-specific mentorship/network, a defined cohort structure).
- Application page and criteria live and clear (stage, thesis fit, what's
  expected in 12 weeks, what founders get: capital, mentorship, Demo Day).
- Hub skeleton stood up as the holding pen for anyone not ready to apply yet
  (waitlist/newsletter, not a full Discord community rebuild by default —
  revisit if a broader Bitcoin-builder community becomes a deliberate goal).

## Phase 1 (weeks 3–8): Application window — direct founder outreach
- **Warm channels first**: Fulgur Ventures / Initial Capital portfolio and
  network, Bitcoin dev communities (Chaincode Labs residents/alumni, Bitcoin
  hackathon participants — Ordinals/Lightning/sidechain hackathons), existing
  founder personal networks. Direct, personalized outreach outperforms
  broadcast for a pool this specific.
- **Public build-in-public thread** on X from the founder(s)/team — not
  community hype, but credibility: why this cohort, why now, what "good"
  looks like for an applicant.
- Presence at (or sponsorship of) 1–2 Bitcoin-specific events in the window
  (e.g. Bitcoin++, Adopting Bitcoin, a regional Lightning hackathon) — this
  audience is small enough that in-person/IRL still outperforms paid social.
- Hard application deadline stated everywhere from day one — urgency without
  a deadline doesn't convert a founder pool this deliberate.

## Phase 2 (weeks 9–20): Cohort runs, next-cycle pipeline builds quietly
- Marketing shifts from "apply now" to **build-in-public from inside the
  cohort**: weekly founder progress updates, mentor sessions, milestones —
  this is the credibility asset that makes the *next* application window
  convert better than the first.
- Hub stays active for the wider Bitcoin builder audience (alumni, rejected
  applicants worth re-engaging, prospective mentors/investors) — low-effort
  cadence, not a full content engine.
- Start warming the next cohort's pipeline in the final weeks of this phase
  (soft "applications open soon" signal) rather than a cold start at week 21.

## Phase 3 (weeks 21–24): Demo Day
- Demo Day is the forcing event — invite investors (Fulgur/Initial Capital
  network first), press, and the wider Bitcoin builder audience.
- This is also the single best top-of-funnel moment for the *next*
  application cycle: every Demo Day attendee who isn't already a founder is
  a warm next-cohort applicant.
- North-star metric for the cycle: **founders who ship something real by
  Demo Day**, not applications received — application volume is a leading
  indicator, shipped progress is what actually sells the next cohort.
